## 1. 教学目标与范围

面向普通用户和初级开发者，不要求会写代码。完成后能追踪同一个请求在对话界面、Agent 运行时、本地资源和模型服务之间的变化；能解释为什么一条用户请求可能触发多次模型调用，以及文件和 Skill 内容何时进入模型上下文。

主线是一个持续可见的 Agent 对话框。贯穿任务为“请读取 notes/project.md，并按项目摘要 Skill 用三条要点总结”。前两幕使用“用一句话解释什么是 Agent”的基础问题，从普通回答、单次文件读取逐步加深到 Skill 与两次工具调用，均使用同一个教学工作区。首版只允许选择预设问题及正常/文件读取失败/流中断分支，不用自由输入冒充可回答任意问题的 Agent。

包含六幕、播放/暂停/单步/回看、原始数据展开、文件预览与本地 Skill 渐进加载。首版使用一个工具 read_file，展示两种读取对象：普通项目文件和 Skill 的 SKILL.md。工具名和工作区约定是本项目教学设计。

延期：真实模型接入、真实用户文件读取、命令执行、写文件、MCP、多 Agent、多个并行调用、多协议切换、任意问题生成、真实 Token/费用/延迟统计。当前不改变静态部署或凭据边界。

### 职责边界

- 对话框展示用户消息、公开助手正文、工具活动与执行结果。工具活动卡是应用视图，并不意味着协议里存在同名聊天角色。
- Agent 运行时整理指令、历史和工具定义，解析响应、校验调用并分派工具；它可以部署在本地应用或后端。本章左侧“本地”指所选教学运行时可访问的工作区。
- 模型服务生成正文或调用请求。自定义 read_file 的执行器拥有文件访问能力；工具定义只告诉模型可用接口，不会把所有文件自动上传。
- Skill 提供工作方法和可选资源，read_file 提供操作。Skill 不自动授予文件权限；本章把读 SKILL.md 表达为一次 read_file 调用，是教学宿主的实现选择。
- 生产环境的接入层可持有服务凭据；本章只画抽象接入节点，不展示真实网络、凭据或服务内部推理。

### 不可混淆的结束条件

一次模型响应 completed 不等于用户任务完成：响应中可能只有工具调用，Agent 仍需执行并续请求。工具参数 done、输出项 done、整次响应 completed 和整项任务 finished 分别展示。

SSE 事件、网络读取片段和模型 Token 边界不同。演示按预设的已解析事件推进，不把“逐字动画”解释为真实 Token 流。正文 done 的最终文本用于核对/替换，不能再次追加。

## 3. 示例与数据契约

### 3.1 预设工作区

所有内容为自主编写的教学数据；不会读取本仓库同名真实文件。

`notes/project.md`：

```markdown
# LLM Lens

目标：用交互演示帮助初学者理解语言模型。
技术：Vite、React、TypeScript 和 Motion。
部署：GitHub Pages；教学模拟不连接真实模型。
```

`skills/project-summary/SKILL.md`：

```markdown
---
name: project-summary
description: 读取项目说明并整理为三条中文摘要。
---

先读取用户指定的项目说明文件。
摘要依次覆盖目标、技术和部署。
只依据已读内容，不补写不存在的事实。
```

初始 Skill 目录元信息仅含 name、description、path。右侧首个请求会显示这些元信息；左侧未读取的正文仍留在文件中。选用 Skill 不保证模型永远正确遵循，本演示的确定性行为来自预设脚本。

### 3.2 工具定义及请求

以下为教学请求形状，可解析 JSON；占位模型不可直接调用。read_file 为自定义函数，并非服务商内置工具。

```json
{
  "model": "<responses-compatible-model>",
  "instructions": "根据已读资料回答。工作区文件与 Skill 正文使用 read_file 读取。可用 Skill：project-summary；描述：读取项目说明并整理为三条中文摘要；路径：skills/project-summary/SKILL.md。",
  "input": [
    { "role": "user", "content": "请读取 notes/project.md，并按项目摘要 Skill 用三条要点总结。" }
  ],
  "tools": [
    {
      "type": "function",
      "name": "read_file",
      "description": "读取教学工作区中指定文件的完整 UTF-8 文本。",
      "parameters": {
        "type": "object",
        "properties": { "path": { "type": "string" } },
        "required": ["path"],
        "additionalProperties": false
      },
      "strict": true
    }
  ],
  "parallel_tool_calls": false,
  "stream": true
}
```

首版固定串行，只允许两条预设路径。运行时验证工具名、完整参数、路径白名单与调用关联；JSON Schema 约束不能代替运行时访问检查。拒绝访问或读取失败属于工具结果，不能被显示为模型已成功读到文件。

### 3.3 以文件读取为例的调用与回传摘录

下面是 Responses 输出项和后续输入项的结构摘录，不是完整响应。示例 ID 都是教学 ID。

```json
{
  "type": "function_call",
  "id": "fc_file",
  "call_id": "call_file",
  "name": "read_file",
  "arguments": "{\"path\":\"notes/project.md\"}"
}
```

```json
{
  "type": "function_call_output",
  "call_id": "call_file",
  "output": "# LLM Lens\n目标：用交互演示帮助初学者理解语言模型。\n技术：Vite、React、TypeScript 和 Motion。\n部署：GitHub Pages；教学模拟不连接真实模型。\n"
}
```

左侧预览、中央结果卡和右侧 output 必须来自同一字符串，摘要预览可以折叠，但不能偷偷改掉实际输出。Skill 正文同样通过 call_skill 对应的 function_call_output 返回，属于工具读取的数据，不擅自升级成 system/developer 消息。

续请求统一采用显式历史：本轮 input = 既有输入项 + 前一响应全部必要 output 项 + 新 function_call_output；重新提供本章 instructions、tools、stream 和串行配置。保留返回的必要 reasoning 项但不展示或编造隐式思考。首版不混用 previous_response_id，以便学习者看见具体新增内容；ID 引用方式可在概念气泡解释。

### 3.4 回放事件与完整轮次

最终 fixture 应包含所选正常路径的完整生命周期；以下只描述事件映射，不能用本表冒充完整 SSE 抓包。

| 原始事件/本地步骤                                       | 状态变化                               | 画面                                   |
| ------------------------------------------------------- | -------------------------------------- | -------------------------------------- |
| response.created / in_progress                          | 当前响应开始                           | 右侧标明第 N 次 POST 与响应 ID         |
| output_item.added（function_call）                      | 建立调用项，保存 id 与 call_id         | 中央新增“准备调用”卡                   |
| function_call_arguments.delta                           | 按 item_id/output_index 累积参数字符串 | 右侧参数增量，中央卡只显示准备状态     |
| function_call_arguments.done / output_item.done         | 核对完整参数与调用项                   | 完整路径及校验状态                     |
| response.completed（含函数项）                          | 本次模型响应结束，任务仍待工具         | 右侧响应结束；中央进入执行状态         |
| 本地 tool-start → tool-result                           | 执行一次教学读取，关联 call_id         | 左侧文件高亮、正文预览，中央结果卡完成 |
| 本地 request-send                                       | 结果进入下一次 POST 的 input           | 结果副本移动到右侧，请求轮次增加       |
| output_item/content_part.added + output_text.delta      | 建立助手正文并累积文本                 | 右侧文本增量到达中央回答               |
| output_text.done / content_part.done / output_item.done | 核对正文和对应项结束                   | 不重复追加最终文本                     |
| response.completed（无待执行调用）                      | 本例 task finished                     | 中央回答完成，输入区可开始新的教学回放 |

含 Skill 的完整脚本为：请求 1 → 模型调用 read_file(SKILL.md) → 响应 1 结束 → 本地加载正文 → 请求 2 携带结果 → 模型调用 read_file(project.md) → 响应 2 结束 → 本地读取项目说明 → 请求 3 携带结果 → 文本流 → 响应 3 结束 → 任务完成。

文件失败分支：读取 project.md 返回自定义字符串化错误对象 `{"ok":false,"code":"FILE_NOT_FOUND","path":"notes/project.md"}`，通过原 call_id 回传；下一响应说明无法完成摘要，不伪造成功文件内容。流中断分支：保留已接收内容，响应标为 interrupted，任务不显示正常成功；重播恢复预设起点，不自动重试。

## 4. 教学简化与准确性边界

- “本地工作区”是静态 fixture，中央 Agent、网络包和服务器均为教学仿真；顶部持续显示“教学模拟 · 不发送真实请求”。
- 服务侧仅有“接收上下文 / 生成输出”抽象状态，不画虚构神经网络活动或内部推理文字。等待文案标为状态提示。
- 只回放一个调用项、一块正文、串行执行。三个模型轮次是本例选定流程，不声称每个 Agent 请求都固定三轮。
- Skill 的自动选择是预设分支。首版演示本地目录与按需读取；不暗示所有 Skill 都以函数调用加载，也不否认托管环境的 Skill 支持。
- 原始事件时序、文本分片与动画时间是示意。无预设百分比“思考进度”、Token 数或费用。
- 文件内容是工具提供的数据，是否遵循 Skill 由宿主与指令语义决定；不把任意文件里的指令画成更高优先级的系统规则。

## 5. 逐幕设计

每一幕沿用同一个中央对话框与两侧位置。前五幕是可独立重播的放大讲解，第六幕连贯播放完整任务。深链接进入各幕时采用明确的初始快照，不依赖用户已播放前一幕。

| 幕                   | 学习目标                             | 初始 → 动作 → 最终                                                              | 动画含义与交互                                                                                |
| -------------------- | ------------------------------------ | ------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| 1 从输入到请求       | 看见用户文本怎样成为输入数据         | 待发送 → 用户气泡 → 指令/历史/工具定义进入请求 → 服务接收                       | 蓝色用户文本副本移动到右侧 input；发送教学问题、单步、展开请求；文件正文尚未上传              |
| 2 回答怎样流回来     | 分清接收事件与界面渲染               | 简单文本请求已发送 → 分片事件 → 同一助手气泡增长 → completed                    | 紫色 delta 从右到中，已展示文字绿标；暂停、查看事件；不用另一个假打字定时器制造回答           |
| 3 模型提出工具调用   | 工具请求由模型输出，执行由运行时负责 | 项目读取请求 → 函数项及参数流 → 完整校验 → 响应结束、待执行                     | 调用卡逐步补全名称/参数；左侧执行器在校验完成前保持空闲；查看 call_id 和参数片段              |
| 4 文件进入上下文     | 看清文件 → 工具结果 → 新请求         | 已完成调用 → focus 文件 → 正文预览 → 中央 result → 下一 POST → 摘要流           | 定点高亮文件，选中正文副本进入中央，再复制到右侧 input；单步停在三个落点、正常/失败分支       |
| 5 Skill 是怎样用上的 | 区分元信息、正文与实际操作           | 请求只含目录 → 选用 Skill → 读取 SKILL.md → 正文进入上下文 → 按步骤读取项目文件 | 左侧 Skill 元信息卡与正文分开；正文只有读后才进入请求；高亮正文中的“目标/技术/部署”与输出映射 |
| 6 一次请求，完整循环 | 把前五幕串成一个用户任务             | 一条消息 → 两个工具调用与结果 → 三轮模型通信 → 三条摘要                         | 右侧按轮次累积，中央保留整段会话；播放、暂停、单步、回看、流中断分支；回看不执行工具          |

### 5.1 视觉与空间

桌面舞台三栏比例建议约 25% / 50% / 25%，中央是视觉主角，整体在标题与反馈/导航之间居中。空间不足自然增加页面高度，不为塞下三栏而缩小字号。

| 左：Agent 本地                                 | 中：Agent 对话                                                      | 右：模型通信                                                   |
| ---------------------------------------------- | ------------------------------------------------------------------- | -------------------------------------------------------------- |
| 工作区树、Skill 目录、执行器状态、文件正文预览 | 标题与模拟标记、用户消息、工具活动卡、助手流式正文、稳定输入/操作槽 | 第 N 次请求、上下文组成、服务抽象节点、当前 SSE 事件、结束状态 |

复用当前白底、细线、留白、圆角、轻阴影和 lucide 图标。输入/请求使用现有 blue，模型输出/调用参数使用 purple，已接收结果使用 green；状态同时有文字与图标，错误文字不靠颜色辨认。复用 tokens.css 字号和行高，不新建深色终端风格。

中央尽可能模拟常见 Agent 产品：底部输入框、发送/停止回放、角色头像、公开助手文本、可展开工具卡、准备/执行/完成状态及历史滚动。因为是预设教学，输入框显示当前教学问题并只读，旁边提供问题选择；不展示无效附件、模型选择或虚假可点击按钮。

工具活动卡默认“读取 notes/project.md · 已完成”，展开显示参数、call_id 和完整结果。普通正文是可读中文，原始 JSON/SSE 作为详情展开。屏幕上的流动元素是数据副本，消息、文件和历史记录保留原位，避免“上传后文件消失”的误解。

### 5.2 动画参数（已实现并浏览器核对）

- 文件 focus 指视觉聚焦：预留边框着色 160–220ms，正文预览淡入约 180ms；不抢走键盘焦点，不对整屏放大。
- 文件正文 → 工具 result → 下一轮 input，分两段约 350–450ms 的数据副本运动，每段在稳定落点显示标签。仅移动副本，不驱动整栏高度或相邻控件位置。
- 公开正文每次按已到达 delta 更新；增量与本地步骤示意播放间隔 1000ms，生命周期步骤 450ms，均非真实延迟。活动项短淡入，不给每个字符弹跳。
- 定点高亮只强调当前因果步骤，其他区域保持可读；无无限闪烁或全屏遮罩。
- 暂停、切幕、回看、重播能打断动画；状态归并先发生，Motion 是表达层。播放游标决定演示推进，动画完成回调不能执行工具或提交请求。
- 减少动态效果时数据原地显现，用标签和静态连接表示来源，仍支持所有步骤；不一次跳过关键教学状态。

### 5.3 布局稳定、响应式与可访问性

- 按全部预设分支给工具卡、预览、状态说明留足槽位；中央历史在自己的区域增长/滚动，输入框和播放控制不随结果追加上下跳动。自动滚动仅在用户仍靠近底部时进行，否则显示“有新内容”。
- 长结果可展开并局部滚动，不能剪掉实际结果冒充完整。代码区域可局部横向滚动，页面不得水平溢出。
- 约 1100px 以下优先改为中央对话框 + 下方“本地/模型通信”详情切换；精确断点实施时以实际文字可读宽度测量。320px 下保持单栏、自然页面滚动。
- 当前步骤同步出现在详情标签摘要，即使未打开右侧也能知道发生了新事件。窄屏不强制自动切标签或搬走中央对话框。
- 工具详情按钮提供 aria-expanded，重要阶段由独立 role=status 播报，不让每个 delta 触发屏幕阅读器重复读全文。解释气泡支持 hover/focus/tap，预览占位 aria-hidden。
- 对话输入框中方向键和空格遵循表单行为；上一幕/下一幕沿用现有键盘约定，不拦截编辑/滚动操作。静态文件内容不能误用成会抢焦点的模态框。

## 6. 实现方案与复用评估

### 方案比较

| 方案                   | 优点                                             | 代价/限制                                          | 结论         |
| ---------------------- | ------------------------------------------------ | -------------------------------------------------- | ------------ |
| 固定视频或纯动画       | 制作路径较短                                     | 无法展开数据或验证回看状态，交互弱                 | 不作为主方案 |
| 预设事件驱动的交互仿真 | 可单步、回看、核对请求内容；静态部署，输出可复现 | 明确标示模拟，不能回答任意问题                     | 推荐首版     |
| 真模型 + 真工具        | 可展示实际请求结果                               | 需要后端/凭据/文件权限；输出不稳定，课堂流程难控制 | 独立后续范围 |

当前源码事实为 Vite + React + TypeScript + Motion；工程规范已说明 AGENTS.md 中旧 Astro/MDX 指令由获批重建方案覆盖。当前没有 DemoShell 或 sitePath，不新增 Astro/MDX 或照旧名称编写不存在的复用入口。

### 模块边界（已实现）

- `src/core/agent-conversation/`：纯类型、fixture、事件归并与状态重建。核心不依赖 React/DOM/网络/时钟。
- `src/features/agent-conversation/`：AgentDeck、中央对话、工作区预览、通信面板、数据运动和 useAgentPlayback。状态来自核心；定时器和可见性监听归 UI。
- `src/app/route.ts`：新增 `#/agent/1` 至 `#/agent/6`，保留 Token 路由与深链接。主题元信息传给专注工具栏、目录、文档标题；当前这些入口硬编码 token，需要同步调整。
- `src/components/`：复用 Concept、MotionPreference；仅为真实重复的标题/导航职责提取小型共享组件，不复制 TokenDeck，也不重构整站通用课程引擎。
- `src/styles/`：沿用 deck/shell/tokens，增添本主题布局样式。右侧容器是请求/响应查看器，不是另一个模型聊天窗口。

三种状态必须分开：回放 `idle/playing/paused/finished`；单轮响应 `waiting/streaming/completed/interrupted`；核心任务 `active/finished/blocked`；显式取消由播放控制器单独记录，停止后不允许继续，只能重播。工具卡另有 `assembling/ready/running/succeeded/failed`。响应 completed 时，存在调用项则任务继续。

每个事件具有稳定 eventId、roundId、itemId/callId 和来源；核心按事件前缀纯归并重建状态。回看不发送、不执行、不增加调用计数。UI 的“继续”只恢复回放游标；重播清理局部状态并从本幕起点开始。目录/设置打开或页面后台暂停，关闭/回前台不自动恢复；换主题清理定时器。

实现入口为 `#/agent/1` 至 `#/agent/6`；两个主题按需加载。第一阶段完成纯状态、fixture 和三栏静态排布；第二阶段完成六幕与数据流动画；第三阶段补异常分支、响应式/键盘/减少动态效果并做浏览器验收。先用单个文件读取验证数据贯穿，再组合 Skill 两次调用；不引入 API SDK、全局状态库或通用动画 DSL。

## 7. 可执行验收

以下验收已执行；浏览器证据与自动化结果见任务归档。

1. 同一文件正文在左侧预览、中央结果与右侧请求中一致；call_id 从调用到结果保持一致。未读取文件正文不提前进入请求。
2. 参数增量到达时不执行；参数完成、响应结束、校验通过后才进入本章执行步骤。每个工具调用在一次前向播放中最多产生一个模拟执行结果。
3. Skill 元信息初始可见，正文只在读取后出现；完整脚本确有两次工具读取、三次模型请求，并能展开各轮新增上下文。
4. 最终摘要覆盖示例的目标、技术、部署；普通正文流与工具参数流分开；done/completed 不重复追加文本。模型响应结束与 Agent 任务完成分别显示。
5. 失败结果可回传但不伪造文件；中断保留已到达内容且不标成功。停止与暂停分别表示任务取消和教学暂停。
6. 单步、暂停、连续播放、任意回看、重播、切幕可得到相同确定状态；回看不重执行、不触发真实文件或网络访问。
7. Token 六幕、首页、目录、显示设置、仓库子路径、文档标题和深链接保持可用；本主题可由首页/目录进入。
8. BetterWright 检查桌面、390px、320px、短视口及 200% 字体；每幕测量实际内容整体上下居中，空间充足时留白差 ≤1 CSS px；空间不足自然滚动，末尾可到达。
9. 追加消息、展开结果、失败、快速切幕时，按钮/导航等非教学锚点偏移 ≤1 CSS px；检查普通动画过程帧，截图必须实际查看。
10. 键盘与减少动态效果完整可操作；文件视觉 focus 不抢键盘焦点；查看历史不被自动滚动拉回底部。

核心测试重点：参数归并、call_id 对应、一次性结果、历史重建、终止语义、重复全文防护与两种异常。实施后运行 `npm run verify`，再用 BetterWright 验证受影响交互；截图和测试证据落入任务规格。
