## 1. 教学目标与范围

面向普通用户和初级开发者，不要求会写代码。完成后能追踪同一个请求在对话界面、Agent 运行时、本地资源和模型服务之间的变化；能解释为什么一条用户请求可能触发多次模型调用，以及文件和 Skill 内容何时进入模型上下文。

主线是一个持续可见的 Agent 对话框。贯穿任务为“请读取 notes/project.md，并按项目摘要 Skill 用三条要点总结”。前两幕使用“用一句话解释什么是 Agent”的基础问题，从普通回答、单次文件读取逐步加深到 Skill 与两次工具调用，均使用同一个教学工作区。演示只使用场景预设问题及正常/文件读取失败/流中断分支，不用自由输入冒充可回答任意问题的 Agent。

包含一个完整演示、发送启动、场景内执行读取、重新发送、按需数据展开、文件预览与本地 Skill 渐进加载。底部播放/单步/回看条已纳入移除范围。首版使用一个工具 read_file，展示两种读取对象：普通项目文件和 Skill 的 SKILL.md。工具名和工作区约定是本项目教学设计。

延期：真实模型接入、真实用户文件读取/写入、命令执行、MCP、多 Agent、多个并行调用、多协议切换、任意问题生成、真实 Token/费用/延迟统计。当前不改变静态部署或凭据边界。

### 职责边界

- 对话框展示用户消息、公开助手正文、工具活动与执行结果。工具活动卡是应用视图，并不意味着协议里存在同名聊天角色。
- Agent 运行时整理指令、历史和工具定义，解析响应、校验调用并分派工具；它可以部署在本地应用或后端。本章左侧“本地”指所选教学运行时可访问的工作区。
- 模型服务生成正文或调用请求。自定义 read_file 的执行器拥有文件访问能力；工具定义只告诉模型可用接口，不会把所有文件自动上传。
- Skill 提供工作方法和可选资源，read_file 提供操作。Skill 不自动授予文件权限；本章把读 SKILL.md 表达为一次 read_file 调用，是教学宿主的实现选择。
- 生产环境的接入层可持有服务凭据；本章只画抽象接入节点，不展示真实网络、凭据或服务内部推理。

### 不可混淆的结束条件

一次模型响应 completed 不等于用户任务完成：响应中可能只有工具调用，Agent 仍需执行并续请求。工具参数 done、输出项 done、整次响应 completed 和整项任务 finished 分别展示。

SSE 事件、网络读取片段和模型 Token 边界不同。演示按预设的已解析事件推进，不把“逐字动画”解释为真实 Token 流。正文 done 的最终文本用于核对/替换，不能再次追加。

## 3. 示例与数据契约

### 3.1 预设工作区

所有内容为自主编写的教学数据；不会读取本仓库同名真实文件。

`notes/project.md`：

```markdown
# LLM Lens

目标：用交互演示帮助初学者理解语言模型。
技术：Vite、React、TypeScript 和 Motion。
部署：GitHub Pages；教学模拟不连接真实模型。
```

`skills/project-summary/SKILL.md`：

```markdown
---
name: project-summary
description: 读取项目说明并整理为三条中文摘要。
---

先读取用户指定的项目说明文件。
摘要依次覆盖目标、技术和部署。
只依据已读内容，不补写不存在的事实。
```

初始 Skill 目录元信息仅含 name、description、path。右侧首个请求会显示这些元信息；左侧未读取的正文仍留在文件中。选用 Skill 不保证模型永远正确遵循，本演示的确定性行为来自预设脚本。

### 3.2 工具定义及请求

以下为教学请求形状，可解析 JSON；占位模型不可直接调用。read_file 为自定义函数，并非服务商内置工具。

```json
{
  "model": "<responses-compatible-model>",
  "instructions": "根据已读资料回答。工作区文件与 Skill 正文使用 read_file 读取。可用 Skill：project-summary；描述：读取项目说明并整理为三条中文摘要；路径：skills/project-summary/SKILL.md。",
  "input": [
    { "role": "user", "content": "请读取 notes/project.md，并按项目摘要 Skill 用三条要点总结。" }
  ],
  "tools": [
    {
      "type": "function",
      "name": "read_file",
      "description": "读取教学工作区中指定文件的完整 UTF-8 文本。",
      "parameters": {
        "type": "object",
        "properties": { "path": { "type": "string" } },
        "required": ["path"],
        "additionalProperties": false
      },
      "strict": true
    }
  ],
  "parallel_tool_calls": false,
  "stream": true
}
```

首版固定串行，只允许两条预设路径。运行时验证工具名、完整参数、路径白名单与调用关联；JSON Schema 约束不能代替运行时访问检查。拒绝访问或读取失败属于工具结果，不能被显示为模型已成功读到文件。

### 3.3 以文件读取为例的调用与回传摘录

下面是 Responses 输出项和后续输入项的结构摘录，不是完整响应。示例 ID 都是教学 ID。

```json
{
  "type": "function_call",
  "id": "fc_file",
  "call_id": "call_file",
  "name": "read_file",
  "arguments": "{\"path\":\"notes/project.md\"}"
}
```

```json
{
  "type": "function_call_output",
  "call_id": "call_file",
  "output": "# LLM Lens\n目标：用交互演示帮助初学者理解语言模型。\n技术：Vite、React、TypeScript 和 Motion。\n部署：GitHub Pages；教学模拟不连接真实模型。\n"
}
```

左侧预览、中央结果卡和右侧 output 必须来自同一字符串，摘要预览可以折叠，但不能偷偷改掉实际输出。Skill 正文同样通过 call_skill 对应的 function_call_output 返回，属于工具读取的数据，不擅自升级成 system/developer 消息。

续请求统一采用显式历史：本轮 input = 既有输入项 + 前一响应全部必要 output 项 + 新 function_call_output；重新提供本章 instructions、tools、stream 和串行配置。保留返回的必要 reasoning 项但不展示或编造隐式思考。首版不混用 previous_response_id，以便学习者看见具体新增内容；ID 引用方式可在概念气泡解释。

### 3.4 回放事件与完整轮次

最终 fixture 应包含所选正常路径的完整生命周期；以下只描述事件映射，不能用本表冒充完整 SSE 抓包。

| 原始事件/本地步骤                                       | 状态变化                               | 画面                                   |
| ------------------------------------------------------- | -------------------------------------- | -------------------------------------- |
| response.created / in_progress                          | 当前响应开始                           | 右侧标明第 N 次 POST 与响应 ID         |
| output_item.added（function_call）                      | 建立调用项，保存 id 与 call_id         | 中央新增“准备调用”卡                   |
| function_call_arguments.delta                           | 按 item_id/output_index 累积参数字符串 | 右侧参数增量，中央卡只显示准备状态     |
| function_call_arguments.done / output_item.done         | 核对完整参数与调用项                   | 完整路径及校验状态                     |
| response.completed（含函数项）                          | 本次模型响应结束，任务仍待工具         | 右侧响应结束；中央进入执行状态         |
| 本地 tool-start → tool-result                           | 执行一次教学读取，关联 call_id         | 左侧文件高亮、正文预览，中央结果卡完成 |
| 本地 request-send                                       | 结果进入下一次 POST 的 input           | 结果副本移动到右侧，请求轮次增加       |
| output_item/content_part.added + output_text.delta      | 建立助手正文并累积文本                 | 右侧文本增量到达中央回答               |
| output_text.done / content_part.done / output_item.done | 核对正文和对应项结束                   | 不重复追加最终文本                     |
| response.completed（无待执行调用）                      | 本例 task finished                     | 中央回答完成，输入区可开始新的教学回放 |

含 Skill 的完整脚本为：请求 1 → 模型调用 read_file(SKILL.md) → 响应 1 结束 → 本地加载正文 → 请求 2 携带结果 → 模型调用 read_file(project.md) → 响应 2 结束 → 本地读取项目说明 → 请求 3 携带结果 → 文本流 → 响应 3 结束 → 任务完成。

文件失败分支：读取 project.md 返回自定义字符串化错误对象 `{"ok":false,"code":"FILE_NOT_FOUND","path":"notes/project.md"}`，通过原 call_id 回传；下一响应说明无法完成摘要，不伪造成功文件内容。流中断分支：保留已接收内容，响应标为 interrupted，任务不显示正常成功；重播恢复预设起点，不自动重试。

## 4. 教学简化与准确性边界

- “本地工作区”是静态 fixture，中央 Agent、网络包和服务器均为教学仿真；顶部持续显示“教学模拟 · 不发送真实请求”。
- 服务侧仅有“接收上下文 / 生成输出”抽象状态，不画虚构神经网络活动或内部推理文字。等待文案标为状态提示。
- 只回放一个调用项、一块正文、串行执行。三个模型轮次是本例选定流程，不声称每个 Agent 请求都固定三轮。
- Skill 的自动选择是预设分支。首版演示本地目录与按需读取；不暗示所有 Skill 都以函数调用加载，也不否认托管环境的 Skill 支持。
- 原始事件时序、文本分片与动画时间是示意。无预设百分比“思考进度”、Token 数或费用。
- 文件内容是工具提供的数据，是否遵循 Skill 由宿主与指令语义决定；不把任意文件里的指令画成更高优先级的系统规则。

## 5. 工作台交互设计（2026-10-12 改版）

当前修改依据用户对原版截图的明确反馈：[改版规格](../../qb-spec/archive/2026/QB-20261012-agent-workbench/spec.md)。第 2–4 节技术契约不变；本次更新教学触发与可视化，不增加真实命令或 API 调用。2026-10-10 旧版证据保留在原归档。

### 单一完整演示

根据用户最新请求合并为 `#/agent`，不再分章节。一次发送依次完成：模型提出读 Skill → 用户触发加载 → Skill 结果进入第二轮请求 → 模型提出读项目文件 → 用户触发读取 → 结果进入第三轮请求 → 流式摘要。仍可选择文件缺失与流中断分支；旧 `#/agent/1` 至 `#/agent/6` 统一映射到本演示，Token 六章独立保留。

本次规格：[单一演示与任务卡关联查看](../../qb-spec/archive/2026/QB-20261012-agent-unified/spec.md)。卡片选择只读取已有状态，不能重发请求、回退任务或重复执行。调用卡选中时恢复服务→Agent 的调用线及 Agent→文件操作线；已有结果再恢复终端→Agent 结果线。接收工具结果卡关联此前工具的结果链，生成回答卡关联正文接收。尚未执行的文件连线用“待读取”与静态虚线区分；选中自动打开对应文件。再次选中同一卡或“跟随当前流程”恢复实时连接，发送/执行/重置清除历史选择。

详情从行内折叠迁移到 dialog：请求按指令/输入消息/工具定义/工具结果渲染；调用按名称/参数/结果渲染；回答按最终正文与增量渲染。原始数据为可切换视图。弹窗只看数据，打开暂停，关闭不自动恢复，焦点返回原触发按钮。

目录树按最长文件名/目录名及图标预算宽度，预留选中/已读图标和最大名称的隐藏宽度预算；名称不换行，展开或读取不带动编辑器横向跳动。窄屏保持已有堆叠布局，名称本身不折行。

### 三个区域

- 左侧：工作区窗口，目录可展开，文件可点开。中部文件编辑器显示带行号的预设内容；用户预览文件不等于 Agent 已读，也不进入模型上下文。下部工具终端记录 read_file 路径、执行中、文本结果或错误；清楚标为模拟，不能输入任意 shell 命令。教学文件内容不改写本仓库文件。
- 中央：视觉主窗口，消息角色、用户气泡、工具卡和公开回答有层次；输入区保留预设场景问题，发送是唯一启动入口，执行按钮出现在对应调用卡/本地终端。任务完成或取消后可重新发送，重建本场景，无重入并行执行。暂停后发送按钮承担继续动作。

输入区使用一个容器级焦点描边，输入文字与底部按钮留出独立间距，取消 textarea 自身的大偏移焦点框，保留按钮键盘焦点。底部显示 deepseek 模型名称与可用工具数量；数量来自本轮请求 tools，发送前使用预设工具定义（当前1个 read_file），不将两次读取或 Skill 误计为多个可用工具。名称为模拟界面展示，不修改请求协议或连接真实服务。
- 右侧：服务端窗口，简短的“收到请求”“提出工具调用”“生成回答”卡按阶段追加，旧卡保留在上方，新卡从底部进入。参数增量更新同一调用卡，文本增量更新同一生成卡，完整请求和事件细节仅在详情 dialog 按需查看。服务内部计算只抽象表达，不编造推理文本。

三个区域都有明确的窗口边界。2026-10-12 视觉调整采用石墨灰主题：页面背景最深，两侧面板稍亮，中央聊天使用更亮的石墨表面和清晰边框；本地目录、编辑器、近黑终端各有层级，右侧卡片使用低饱和紫灰表面。正文与辅助文字提高对比度，沿用蓝/紫/绿传递含义；连接标签和详情/目录/设置浮层使用同一局部主题。用户随后要求提升为全站主题：首页、Token 和 Agent 统一继承 tokens.css 的石墨灰变量，移除局部主题挂载/清除。详见[全站石墨灰规格](../../qb-spec/archive/2026/QB-20261012-site-graphite/spec.md)。对应规格：[石墨灰主题](../../qb-spec/archive/2026/QB-20261012-agent-graphite/spec.md)。仍沿用全站 blue/purple/green、字号和圆角，不增加大面积装饰。去掉图例、面板教学段落、底部要点、步骤条等重复文本；动作说明集中在线条和任务状态。

### 连线与动画

六种语义传递：输入 → 请求、模型调用 → Agent 调用、Agent 调用 → 本地文件、读取结果 → Agent result、Agent result → 续请求、服务端文本 → 回答。每种连接使用对应内容锚点，不将所有流动连接到整栏中心。线有明确箭头、发送方/接收方端点和短 action 标签。按用户新要求，已出现的语义连接全部保留至重置/重新发送，正常完整链路共10条；连续增量共享一条连接。标签按首次发生顺序编号01/02…，左右轨道各自安排标签，标签使用独立前景图层、窗口间预留通道，旧线降低强调，当前传递与选中关联保持突出。桌面路径仅根据端点生成一段平滑三次曲线，水平切向进出窗口；标签优先放在曲线中部，重叠时沿曲线取其他位置，保持在窗口间通道内，标签背景遮住下方线条。标签位置与避让不改变路径形状。选卡、暂停、停止不清空已有连接；未执行的关联预览仍用待读取区分。多连线 marker 独立，窄屏保留侧边圆角连接及独立标签轨道，按完整轨道容量预留固定间距，不能因追加/选择推动窗口。

区域焦点使用单一覆盖框。当前顺序为连线先由源区块绘向目标（约1150ms、匀速），端点/箭头/action 随抵达出现；随后覆盖框按接收方在三个窗口外缘滑动（约550ms、无弹跳且可重定向）。框抵达后，对应的请求卡、工具卡/result、文件或回答区块增加同色内描边与轻微染色；读取文件时同步突出文件编辑器。新目标到达前保留上一目标高亮。文字/参数增量持续留在同一语义连接，不因每个delta重画或重复滑框；内容继续在约1700ms后呈现。主要自动步骤显示至少2100ms，减少动态效果时使用原教学节奏。历史卡片查看保留全部连接并突出相关静态连线、所选区块与区域边缘，焦点留在所选服务区；减少动态效果立即显示完整静态提示。覆盖框/线/区块高亮不占布局，不拦截输入，动画完成不能执行工具，暂停/停止/重置可立即中断。对应规格：[区域焦点与连线动效](../../qb-spec/archive/2026/QB-20261012-agent-flow-motion/spec.md)。

### 事实、样例与边界

2026-10-13 已读取 [Function calling](https://developers.openai.com/api/docs/guides/function-calling) 的 How it works、tool calling flow、执行并追加结果及串行配置章节：模型提出调用，应用执行并以 call_id 关联返回值，后续请求携带结果。该事实不因工具区布局改变。以下三个函数的名称、访问范围、返回值及候选区/执行区均为项目教学设计，不是 OpenAI 内置文件工具。

| 函数 | 完整参数 | 教学工作区访问范围 | 返回值 |
| --- | --- | --- | --- |
| read_file | `{ "path": "notes/project.md" }` | 已存在的预设文件 | 完整 UTF-8 文本；缺失返回 FILE_NOT_FOUND |
| list_directory | `{ "path": "notes" }` | notes、skills、skills/project-summary | JSON 字符串 `{ "ok": true, "path": "notes", "entries": [{ "name": "project.md", "type": "file" }] }`，只列直接子项 |
| write_file | `{ "path": "notes/summary.md", "content": "# 项目摘要\n…" }` | 仅 notes/summary.md | JSON 字符串 `{ "ok": true, "path": "notes/summary.md", "written": true }`；完成前不创建文件 |

三个 schema 都是 function、strict:true、additionalProperties:false；path 必填，write_file 的 content 也必填。运行时校验工具名、参数字段/类型、路径范围和响应结束门槛。越界、非法参数、重复结果或过早执行不得修改模拟文件。所有文件仅保存在纯回放状态中，重新发送/重置恢复初始文件，绝不读取或写入用户/仓库真实文件。

保留默认“读取并总结”：read_file(SKILL.md) → read_file(project.md) → 三条回答，2 次调用/3 轮请求。新增预设“整理并保存”：list_directory(notes) → read_file(SKILL.md) → read_file(project.md) → write_file(summary.md) → 回答，4 次调用/5 轮请求。文件缺失时读失败后说明原因，不执行写入；流中断保留已执行结果与部分正文，不重复执行。

1. 发送前：显示三个候选工具，执行区固定占位“等待 Agent 调用”。候选条目只介绍能力，不允许绕过 Agent 直接执行。输入区可切换两项预设任务。
