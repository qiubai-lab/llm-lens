# Agent 对话与数据流：实施规格与验证

用户请求开发新演示，并明确“先评估实现方案”。用户随后明确“很好，请你落地实现”，已授权本规格范围的实施。实现与验证已完成。

事实源及完整方案：[技术设计](../../../../demos/agent-conversation/TECHNICAL_DESIGN.md)。遵循项目新演示流程与 UI 规范。当前运行栈以 package.json、源码及 ENGINEERING_STYLE_SPEC 为准。

## 目标与范围

中央始终以 Agent 仿真对话框为主线，左侧展示本地资源，右侧展示模型通信；逐步讲解请求、流式回答、工具调用、文件回传、Skill 和完整循环。首版为预设事件回放，保持 GitHub Pages 静态部署与已有 Token 风格。

不包含真实模型/文件/命令、多 Agent、多协议或自由输入生成。方案选择：推荐事件驱动仿真；固定视频缺少数据交互，真实接入需要额外基础设施且难以稳定教学。

## 需求

- REQ-001：桌面采用本地/对话/通信三栏，中央为主角，窄屏保持对话框可见并切换详情。
- REQ-002：六幕覆盖发送、文本流、工具参数、文件结果回传、Skill 渐进加载和完整循环。
- REQ-003：遵守技术设计的数据和边界；展示 call_id、不同完成状态、完整参数校验及真实的续请求关系。
- REQ-004：支持确定性播放、暂停、单步、回看和重播，回看不得触发执行。
- REQ-005：复用全站令牌、气泡、动态偏好与导航；保持原有主题及子路径兼容。
- REQ-006：提供正常、文件失败和流中断分支，明确模拟，不能伪造成功或真实请求。
- REQ-007：动态布局稳定，键盘、200% 字体、320px 和减少动态效果可用。
